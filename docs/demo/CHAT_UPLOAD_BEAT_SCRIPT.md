4. **（本次更新）Beat 4 整段重寫**：實測證實只送出 `05`（半年電費單）不會被 Gate 放行——

## 開錄前

1. 開站，確認角色 **Supplier**。
2. 展開「顯示案件資訊與進階工具」，點一次「一鍵執行正常案件」健康檢查（確認後端沒問題）。
3. 點「**重置 Demo**」回到乾淨狀態（案件標題「TW-STEEL-01 2026 年度示範案件」，狀態 DRAFT）。
4. 收合面板，開 OBS 開始錄。

---

## 第 0 步｜0:00–0:20　Vault 裝置註冊（Verifier）

切角色到 **Verifier**。在「Vault 裝置」面板按「**註冊 Vault 裝置**」，瀏覽器跳出 WebAuthn
提示（Windows 上是輸入 PIN 碼），完成後按鈕旁狀態變「● 已註冊」。旁白：「Verifier 先用自己
裝置的生物辨識/PIN 註冊一把公鑰，等一下 Supplier 上傳的證據，只要這把公鑰已經註冊，就會自動
用它加密——這是時間點依賴的設計，現在示範清楚這件事。」切回 **Supplier**，準備進入 Beat 1。

## Beat 1｜0:20–0:32　底稿散落

畫面停在剛重置、Evidence Index 空白的狀態。

## Beat 2｜0:32–0:55　Supplier 上傳（用 05 取代 01）

在聊天輸入框**一次選取四張圖**：`05_電費單_異常缺期版.png`、`02_燃料紀錄_2026年度.png`、
`03_產量表_2026年度.png`、`04_前驅物清單_2026年度.png`（電費單刻意用缺期版，不是正常版
`01`——留到 Beat 3 讓 AI 標出來）。畫面依序跳「排隊中…→上傳中，AI 讀取中…→擷取結果卡」，
四份各自獨立平行處理。逐一按「確認並送出」（電費單那張卡片上的涵蓋期間欄位 AI 應該會自動
讀到 `2026-01-01～2026-06-30`，不用手動改；如果沒讀到，手動改成這個範圍再確認）。

## Beat 3｜0:55–1:10　Agent 標異常（自動觸發，不用手動點）

四份都確認完，AI 自動跑完案件分析，**畫面右下角會自動跳出一顆紅色警示氣泡**：

> Evidence Agent 發現 1 項異常
> 電費單 缺期間：2026-07-01/2026-12-31

對著鏡頭唸出來，可以順手點氣泡上的「查看詳情」——會自動展開並捲到「案件資訊與進階工具」
面板，露出完整 RiskReport（`EVIDENCE_PERIOD_INCOMPLETE`、`coveredPeriod`/`missingPeriod`
逐欄位對得上剛剛唸的內容），證明不是隨便編的字，是真的算出來的。**這個面板留著展開**，
後面 Beat 5～7 都在同一個面板裡操作，不用再收合重開。

## Beat 4｜1:10–1:55　Policy Gate 真的擋（分 4a-4d，實測過的真實行為）

**這是全片最重要的一段，展示「Evidence Agent 預審提醒」跟「Policy Gate 真正攔阻」是兩回事。**

- **4a**　直接按「**提交年度資料**」——**成功**，跳出綠色勾勾的「已成功提交」浮動視窗，
  狀態變 `METHOD_REVIEW`，不需要先拿掉電費單那份。旁白：「Evidence Agent 標出來的是預審
  提醒，不會擋提交。」
- **4b**　按「**重驗 Proof / Gate**」——狀態**退回 `NEEDS_EVIDENCE`**，不是 `READY_FOR_
  VERIFIER`。旁白：「但真正決定案件能不能往下走的是 Policy Gate，它會實際重算證據涵蓋期
  間——電費單只蓋了半年，Gate 真的擋下來了，這才是守門員，跟剛剛 Agent 那句『提醒』是分開
  兩層。」
- **4c**　補件：回到聊天輸入框上傳 `01_電費單_2026年度.png`（正常全年版），確認送出。旁白：
  「系統把同一類證據的涵蓋期間做聯集，這份補上去之後電費單就蓋滿全年了。」
- **4d**　再按一次「**重驗 Proof / Gate**」——這次狀態變 `READY_FOR_VERIFIER`。旁白：「補件
  後 Gate 才真的放行，這一步不能跳過、也沒辦法用話術繞過去。」

## Beat 5｜1:55–2:20　最小揭露

切角色到 Importer 看摘要卡；切回 Supplier，在「為 Demo Verifier 建立一次性短效 Grant」面板
選一筆 evidence、按「建立 Grant」；切到 Verifier 用 token 開一次底稿對照。

## Beat 6｜2:20–2:35　授權撤銷

切回 Supplier 按「撤銷 Grant」（畫面提示：「Grant 已撤銷；Verifier 再使用會被拒絕。」）；
切回 Verifier 再試開同一份底稿→被拒，錯誤訊息「Grant 已撤銷，底稿未開啟。／請 Supplier
建立新的短效 Grant。」**這則錯誤現在同時會出現在頁面上方紅色橫幅和右下角 toast 氣泡**，
不用特地捲到最上面。

## Beat 7｜2:35–2:45　終卡：誠實邊界

在同一個「案件資訊與進階工具」面板往下捲（Grant 區塊之後），按「**展示物理真實邊界**」
按鈕。畫面文字：「文件數字彼此一致，但現場儀表失效或未校正，資料一致性不能證明物理真實。」
下一步：「轉交查驗員檢查校正紀錄，並安排實地查驗。」停格 2 秒收尾，這句話跟簡報「AI 可以
找問題，不能判定物理真相」對得上。

## 備援

| 狀況 | 怎麼做 |
|------|--------|
| 紅色氣泡沒跳出來 | 手動展開「顯示案件資訊與進階工具」，捲到 RiskReport 的 Findings／Missing evidence 表格唸給觀眾聽 |
| AI 沒讀出涵蓋期間、預覽卡片顯示整年 | 手動改卡片上的日期輸入框成 `2026-01-01～2026-06-30` 再確認 |
| 提交失敗 | 檢查是不是 4 份都已按「確認並送出」（未確認會擋提交，缺期不會） |
| 4b 重驗後沒有退回 `NEEDS_EVIDENCE` | 確認電費單真的是用 `05`（半年版）不是 `01`（全年版）——`01` 涵蓋全年會直接放行，看不到這段落差 |
| 4c 補件後 4d 還是沒放行 | 確認 `01` 那份也按過「確認並送出」，沒確認的證據不會計入涵蓋期間聯集 |
| Vault 註冊按鈕沒反應 | 確認瀏覽器有彈出 WebAuthn 對話框（Windows 可能被其他視窗擋住），或改用手機瀏覽器示範生物辨識 |
